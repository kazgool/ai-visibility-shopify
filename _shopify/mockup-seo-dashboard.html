Notes for the build, not part of the screen

Specification for build step 5. It replaces the prose in PRD-SEO-FULL-ONPAGE.md section 4.1; where the two disagree, this file wins. Two amendments to the PRD are proposed below and need approval before the build starts.

  • Amendment 1: shop-wide findings are separated from per-product ones. A finding that flags every product in the read set is not counted against individual products; it appears once in the "fixes that cover the whole shop" card. Without this the readiness figure is zero on almost every real shop, because one theme-level problem flags all products at once, and a dial pinned at zero tells the merchant nothing and sells nothing. The threshold is exactly 100 percent of the read set, so it is a fact and not a judgement, and the method line says so.
  • Amendment 2: "what to do, worst first" is no longer a separate card. Its content now lives in the two places the merchant is already looking: the shop-wide card, ordered, and the expandable steps inside each readiness group. Keeping a third copy of the same advice was the only alternative.
  • Two label sets, not one. Every string a merchant reads here is a plain rewrite of the technical one. Add OWNER_LABEL beside CHECK_LABEL in seo-findings.ts, keyed by the same codes and covering every code. CHECK_LABEL is not touched: the operator workspace at /app/seo, the CSV export and the weekly diff all keep reading it. Both are typed by FindingCode, so a new check that forgets a plain label fails typecheck rather than shipping jargon.
  • A third constant, OWNER_STEPS, holds the numbered how-to for each code: the sentence, and where in Shopify or the theme it is done. Every code that can appear in a readiness group must have one; a code with no steps fails typecheck. This is what stops the screen from naming a problem and leaving the merchant with nowhere to go.
  • Plain labels and steps never say: canonical, structured data, schema, node, hreflang, GTIN, alt text, lazy load, Open Graph, H1, meta. Check codes never appear on this screen; they stay in the CSV and the operator view.
  • Group assignment must be a total function. Each finding code declares one owner: the merchant, this app, or the theme. A product goes in the group of its most immediate owner, in that order, so the four groups partition the read set exactly and the four numbers add to the denominator. Assert that sum in a test on all five fixture stores.
  • The expandable steps use a native disclosure element, not JavaScript state, so the screen still works if hydration fails. In Polaris this is Collapsible with a button; the closed state must already carry the count and a one-line summary, because a merchant who never opens it still has to know what the group is.
  • Route /app/seo/dashboard. The operator workspace at /app/seo is untouched.
  • Charts are hand-drawn SVG or Polaris Viz. No chart library from a CDN: this app ships no third-party script and this screen is not where that changes.
  • Bar order is by count descending within each column, computed at render. Bar colour is the owning group, so it matches the readiness bar above without a second legend.
  • Checks that found nothing collapse into one sentence per column, with no codes and no count. Not-run and does-not-apply each get their own hatched row and their own sentence; neither ever renders as a zero-width bar with a count of 0.
  • Every dial, gauge and bar carries its raw count beside it. A percentage never appears alone. A measured zero may show as an empty gauge with "0 of 189" under it; a value that was never measured is a sentence, never a gauge.
  • Layout must survive 1440, 1280, 1024, 768 and 375 wide, with no clipped text in any SVG and no gauge label wrapping to three lines. Every SVG scales by viewBox, with no fixed pixel width except the hero dial's max-width.
  • Must read correctly on all five stores: a 50-product fixture, this 189-product shop, a 20,000-product store, an empty store, and a store where the live page read never ran.
  • The figures above are illustrative, drawn to resemble a real client catalogue. Nothing here is a measurement.
